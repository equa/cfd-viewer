# Install with:
#   pip install -r requirements.txt

# Which VTK?
#
# Plain `vtk` from PyPI, 9.4 or newer. Its wheels carry both an EGL and an
# OSMesa render window and pick one at runtime: X11 first, then EGL, then
# OSMesa. That covers headless servers without any special build.
#
# The catch is that VTK *dlopens* libEGL / libOSMesa rather than bundling them,
# so a container needs the system library present:
#
#   apt-get install -y libosmesa6        # Debian/Ubuntu
#   dnf install -y mesa-libOSMesa        # Fedora/RHEL
#
# On a normal Linux workstation this is already installed. Verify with:
#   python -c "import vtk; w=vtk.vtkRenderWindow(); w.SetOffScreenRendering(1); \
#              w.Render(); print(w.GetClassName())"
# Expect vtkOSOpenGLRenderWindow (or vtkEGLRenderWindow on a GPU box).
#
# Fallback -- `vtk-osmesa` statically bundles OSMesa, so it needs no system
# library at all. Use it only where you cannot install libosmesa6, and know
# what you are taking on: it is NOT on PyPI (needs
# `--extra-index-url https://wheels.vtk.org`), it stopped at 9.3.1, and it
# ships wheels only for CPython 3.6-3.12 on Linux x86_64 and Windows. Python
# 3.13+, macOS or arm64 will simply fail to resolve.
#
#   pip install "vtk-osmesa" --extra-index-url https://wheels.vtk.org
#
# Verified on VTK 9.3.1, 9.6.2 and 9.7.
#
# NB this server never RENDERS -- it only extracts, and nothing in server/ calls
# Render(). FoamPipeline used to CONSTRUCT a vtkRenderWindow at init anyway,
# left over from the mothballed Trame front end, and that turned out to matter:
# VTK needs a GL backend PRESENT to construct one, not merely to render into it.
# Dropping libosmesa6/libgl1 from the cfd-viz image on 2026-09-21 failed
# immediately -- "vtkRenderWindow construct ... [FAIL]".
#
# Fixed 2026-09-22 by building it lazily instead (see the render_window property
# in foamviz/pipeline.py), so extraction -- all this server ever does -- needs no
# GL at all, and the cfd-viz image now ships without either package.
#
# Anything that genuinely renders still needs them: screenshot(), write_vtkjs(),
# pick_cor(), and the rendering sections of tests/test_pipeline.py. Verified by
# running that suite with vtkRenderWindow patched to raise: 48 checks pass with
# no GL, and the first failure is pick_cor, which really does render.
#
# This is about the CONTAINER. On a workstation where you actually render --
# running the old Trame front end, or anything that calls Render() -- you still
# want a GL backend installed, per the apt/dnf lines above.
# ---------------------------------------------------------------------------
